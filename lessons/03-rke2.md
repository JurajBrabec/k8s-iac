# Lesson 3 — Build an RKE2 cluster

**Time:** 3 hours. **Level:** intermediate. **Prerequisite:** three reachable VMs and instructor-approved RKE2/Rancher version matrix.

## Objectives and concepts

Install one RKE2 server (control plane and embedded etcd) and two agents. RKE2 runs the Kubernetes control plane, kubelet, container runtime and selected CNI. Rancher Manager is installed separately later. A single etcd server is a single point of failure.

## Exercise

1. On all nodes check `hostname`, `timedatectl`, `free -h`, `df -h`, `getent hosts github.com` and the network rules in the [RKE2 requirements](https://docs.rke2.io/install/requirements). Confirm no existing cluster will be overwritten. Use the same instructor-approved version on all nodes.
2. On the **server**, replace the example IP with its actual address and set the approved version, e.g. `export RKE2_VERSION='v<approved-version>+rke2r1'`:
   ```bash
   sudo mkdir -p /etc/rancher/rke2
   sudo sh -c 'cat > /etc/rancher/rke2/config.yaml' <<'EOF'
   tls-san:
     - "<SERVER_IP>"
   EOF
   curl -sfL https://get.rke2.io -o /tmp/install-rke2.sh
   # Inspect the installer and verify it against the release process before execution.
   sudo env INSTALL_RKE2_VERSION="$RKE2_VERSION" sh /tmp/install-rke2.sh
   sudo systemctl enable --now rke2-server
   sudo journalctl -u rke2-server -n 50 --no-pager
   ```
   Do not include `/` or CIDR in the IP. Wait for initialization. Read the join token securely with `sudo cat /var/lib/rancher/rke2/server/node-token`; treat it as a password.
3. On **each worker**, create `/etc/rancher/rke2/config.yaml` using `sudo` and an editor. Substitute the server IP and token without committing the file or pasting the token into chat:
   ```yaml
   server: https://<SERVER_IP>:9345
   token: <SERVER_NODE_TOKEN>
   ```
   Protect it (`sudo chmod 600 /etc/rancher/rke2/config.yaml`). Set the same `RKE2_VERSION`, then:
   ```bash
   curl -sfL https://get.rke2.io -o /tmp/install-rke2.sh
   sudo env INSTALL_RKE2_TYPE=agent INSTALL_RKE2_VERSION="$RKE2_VERSION" sh /tmp/install-rke2.sh
   sudo systemctl enable --now rke2-agent
   sudo journalctl -u rke2-agent -n 50 --no-pager
   ```
4. On the **workstation**, obtain the kubeconfig securely and update the loopback address to the server IP. Use the same SSH user and address from Lesson 2. This credential is cluster-admin: never commit or share it.
   ```bash
   export SERVER_IP='<SERVER_IP>'
   umask 077
   ssh ubuntu@"$SERVER_IP" sudo cat /etc/rancher/rke2/rke2.yaml > "$HOME/kubeconfig-lab"
   sed -i "s/127.0.0.1/$SERVER_IP/g" "$HOME/kubeconfig-lab"
   export KUBECONFIG="$HOME/kubeconfig-lab"
   kubectl get nodes -o wide
   kubectl get pods -A
   ```
   Retain `KUBECONFIG` in each workstation shell in later lessons. Do not change the default kubeconfig of an unrelated cluster.
5. The instructor installs the tested ingress controller and default IngressClass if not already provided. Verify `kubectl get ingressclass` and that ingress pods are ready. Verify the app and Rancher hostnames resolve to the ingress endpoint on the workstation.

## Acceptance

- The server and configured one to three workers show `Ready`, and core DNS/CNI pods are healthy.
- `kubectl` connects from the workstation with validated TLS. Explain 9345 versus 6443.
- Describe a production design with three server nodes, stable API endpoint and independent backups; do not describe the lab as HA.

**Hints:** On a node, `sudo journalctl -u rke2-server -f` or `rke2-agent -f`; check unique hostnames, token, ports, CNI and DNS. RKE2 binaries are in `/var/lib/rancher/rke2/bin` on nodes. Installer scripts are downloaded from the internet; instructor should review/pin the release artifact process.
